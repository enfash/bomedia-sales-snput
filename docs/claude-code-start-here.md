## Conventions in the code
- Schema `bomedia`. Security-definer `api_*` functions are granted only to `bomedia_financial_runtime`; sign-in functions `auth_*` only to `bomedia_auth_runtime`. New functions must be added to: `lib/server/financial-db.ts` (type, allow-list, and an explicit dispatcher line for no-argument functions), `scripts/migration/provision-auth.mjs`, `verify-financial.mjs` (and `verify-auth.mjs` for `auth_*`).
- Writes are idempotent (`prior_result` + `idempotency_requests`, one `crypto.randomUUID()` request id per unsaved edit) and write `audit_events`. PG error codes map to `FinancialError` (42501 to 403; 22023, 23514, 23505, 22P02 to 409).
- Tests: service tests inject `call`; route tests mock `next/headers`, `./postgres-auth-routes`, `./postgres-auth`; DB tests use PGlite `testDatabase()` inside `begin` with `set local role bomedia_financial_runtime`, a `failure()` savepoint helper, and `reset role` before inserting into restricted tables.
- Every page's back link is the one `BackLink` component (`components/back-link.tsx`, styled by `backLinkStyles` in `app/theme.ts`): arrow plus destination name, left-aligned with the page title. Use it for any new page; do not hand-build a back button. Pages reached from the home screen use `HomeBackLink` (same file), which shows Dashboard for the owner and Home for the cashier from the route; use it instead of a `router.back()` icon button. Only the old legacy Inventory page (to be deleted) still has one.
- Theme rules that bite (learned the hard way, details in the handoff): a button that sets its own colour or fill is fine, because the dark-mode brand colour for outlined and text buttons is a theme `variants` entry that a component's own `sx` overrides; use the exported `accent` for brand-coloured text; a numeric `borderRadius` in `sx` is multiplied by 10, so use px strings; status and tone pills come from `tonePill(tone)` (`app/theme.ts`); anything that depends on saved browser data renders a skeleton until mounted (see `useMounted` in `components/job-board.tsx`).
- Status messages that are not part of the page content (saved on this device, waiting to send, offline, confirmed) are floating toasts, never banners in the page flow: use `useFloatingNotice(id, notice)` from `components/floating-notice.tsx`, or `toast` from sonner for a one-off.
- Logic never lives in a page file: the Records and Job board logic is in `lib/records-view.ts` and `lib/job-board.ts` with tests that pin today's behaviour. Move logic first, with tests, then rebuild the view.
- A production build is checked in an env-free copy of the project (rsync without `.env*`, `cp -Rc node_modules`) so it never reads secrets or overwrites the running preview's `.next`.
- Lagos has no daylight saving; "today" means the Lagos date.
- Migrations are append-only; never edit one that has been applied. Next number is `202610120038` (037 is the owner approvals migration, applied only to PGlite tests so far, not yet to the sandbox database). Adding a migration also means updating `lib/schema-version.ts` (a test fails until it matches the folder).
